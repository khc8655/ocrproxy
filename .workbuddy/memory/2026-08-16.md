## www.khc6.cn 经 EdgeOne 访问 522 排障
- 现象：浏览器访问 www.khc6.cn 打不开，EO 返回 522（回源失败）。
- 链路：DNS 已正确 CNAME 到 EdgeOne（www.khc6.cn → eo.dnse2.com → 43.174.x），EO 控制台回源配到主机 124.223.35.23。
- **根因：腾讯云安全组只放行 80、未放行 443**。外部 TCP 探测 80 通、443 超时；源站 Caddy 80/443(www) 应用层均正常（环回 200），故为云网络层拦截，非应用故障。
- 修复：①治本——安全组入站放行 TCP:443（0.0.0.0/0 或 EO 回源 IP 段）；②应急——EO 回源协议改 HTTP/80（源站 80 已通，绕过 443）。
- 注意：本地 `edgeone` CLI 是 Makers/Pages 命令行，不管理 CDN 回源（回源在 EO 边缘安全加速控制台）。裸域名 khc6.cn 无 A 记录，故打不开属正常。

## OCRProxy Web 管理面板安全风险核查（用户关注核心服务安全）
- OCRProxy = FastAPI 应用，管理面板为 SPA（"LLM Proxy 控制台"），路由：`/` 与 `/admin`（面板 HTML）、`/docs`、`/redoc`（Swagger/ReDoc）、`/api/admin/*`（管理 API）、`/v1/*`（代理 API）。
- **鉴权边界**：
  - `/v1/*`（含 chat/embeddings/rerank/ocr/models）需 `verify_proxy_auth`（Bearer PROXY_API_KEY 或 ADMIN_PASSWORD）。
  - `/api/admin/*`（config/stats/verify-key/test-candidate）需 `verify_admin_auth`。
  - ❌ **裸暴露无鉴权**：`/`（面板 UI）、`/admin`、`/docs`、`/redoc`、`/health`。
- **当前暴露面**：Caddy `:9090` 块反代 8787，但**无 TLS、无 basicauth、无 IP 限制** → 管理面板 UI / Swagger / admin API 全部明文挂在公网（*:9090）。
- 安全配置方向（待用户拍板，未执行）：
  - 对外 API：改走子域 `api.khc6.cn` + Caddy HTTPS:443 → 8787（仅放 /v1/* 等 API 路由，不放 / /admin /docs），弃用裸 9090。
  - 管理面板：方案A（最安全）仅经 WireGuard VPN / SSH 隧道访问 127.0.0.1:8787，完全不暴露公网；方案B（折中）走 `dash.khc6.cn` + Caddy `basicauth` + `remote_ip` allowlist。
  - 前提：腾讯云安全组须放行 443（同 522 排障根因）。
  - 可选应用层加固：给 `/`、`/admin` 加 `verify_admin_auth` 依赖（改 app/main.py）。
- 用户已有 WireGuard VPN + 阿里云聚合网关架构，方案A 与其既有一致、最稳。
