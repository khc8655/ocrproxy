## 登录后加载失败 Bug 修复（agent_models 字典/数组类型错配）
- 现象：用户登录后立即报 `加载失败: (state.config.agent_models || []).map is not a function`。
- 根因：`/api/admin/config` 返回 `agent_models` 为 **dict**（模型名=>{keys:[...]}），但 `updateAccessGuide()`（admin.html:1352，位于 loadAllData 首步）把它当**数组**用 `.map(m => m.model)`；dict 无 .map 方法 → 抛错 → 全链路中断。其余 9 处 agent_models 用法均为 `|| {}`（dict 正确），全文件扫描确认仅此一处同类 bug。
- 修复：改为 `const agentModels = Object.keys(state.config.agent_models || {});`（键即模型名）。
- 验证（真运行时，非仅 curl）：
  - 拉取 VM 真实 /api/admin/config（agent_models 两键：deepseek-v4-flash、step-3.7-flash）。
  - Node harness 跑函数本体：OLD 精确复现 `...map is not a function`；NEW `RUNTIME: OK`，guideAgentModels=`deepseek-v4-flash、step-3.7-flash`。
  - 部署 VM 后，再拉回**线上文件**抽取同名函数 E2E 复跑：通过，旧 `.map` 已不存在。
- 教训：前端修复不能只靠 curl 状态码/grep 验证，JS 运行时类型错误必须函数级执行验证（用真实 API 数据 + node 模拟 DOM）。
