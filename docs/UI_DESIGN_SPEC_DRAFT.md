# OCRProxy 控制台设计规范

> 适用范围：`src/` 下的所有页面、卡片、表格、弹窗与交互。
> 新增页面前先读本规范；页面完成后按文末清单自检。
> 版本：v1.1 · 2026-10-26（补齐 VM / EdgeOne 双形态与知识库节点规范）

---

## 1. 目的

这份规范解决三件事：

1. **页面语义清楚**：每个页面只做一件事，用户一眼知道“这里是管供应商、管模型，还是管 Key”。
2. **视觉与交互统一**：颜色、字号、间距、按钮、状态、图标在所有页面复用同一套规则。
3. **架构不重复**：同一份数据、同一套文案、同一种状态只维护一处，避免页面之间各写一套。

原则：**只呈现真实功能，不为了填满界面而虚构模块。**

## 2. 产品边界与页面语义

### 2.1 概览

**回答的问题**：网关现在暴露了什么？Agent 与知识库运行得怎么样？最近哪里出错了？

包含：

- 接入网关：Base URL、客户端 Key、当前运行模式下真正可用的模型（每个模型后标协议）。
- Agent 对话总览：VM 显示今日 Token、首字延迟、失败与切 Key、热门模型 Top 3；EdgeOne 显示 Key 当前快照。
- 知识库入库总览：对话、向量、重排、OCR 四类入库统计（仅 VM）。
- 最近错误日志：按 Agent / KB 筛选，可清空（仅 VM）。

按运行模式切换可用模型：Agent 模式列出 Agent 模型，KB 模式列出 `chat / embedding / reranker / ocr` 四个虚拟模型及节点数。

不包含：请求趋势图、全局搜索、用户中心、权限管理等没有真实接口的界面。

### 2.2 供应商

**回答的问题**：有哪些上游？每个上游配了哪些 Key？哪些 Key 来自中枢？

- 以**供应商**为单位，一个供应商一行。
- 名称后依次展示：来源、Key 数量、适配版本、支持协议、RPM。
- Key 以胶囊展示“别名 + 来源”；VM 端中枢同步的 Key 带锁且只读，本地 Key 可编辑或删除。
- 有规则更新时在名称后显示“可升级至 V.xxx”，行内点击即可升级；页头支持一次更新全部。
- 顶部工具栏负责名称搜索与排序，不放侧边栏。
- 新增供应商只表达两种来源：自定义（本地）与从中枢按需拉取；不再提供官方预设下拉。
- 不展示 Base URL、Anthropic Base URL、描述等配置细节；这些在编辑弹窗里维护。

### 2.3 模型及路由

**回答的问题**：对外暴露了哪些模型？每个模型挂载了哪些 Key？现在用哪个？出问题怎么切？

页面分两个页签，共用同一套视觉规范：

- **Agent 路由**：以模型为单位，一个模型一张卡；标题下直接进入 Key 列表，中间不放统计块。
  - 表格列：顺序、供应商、Key 别名、来源、状态、最近调用、操作。
  - 操作：切换主力 Key、探测连通性、移除绑定。
  - 模型 ID 与上游模型 ID 分开；上游模型可通过供应商适配规则探测回填。
- **知识库**：固定 `chat / embedding / reranker / ocr` 四个虚拟模型，每个模型下挂载候选节点。
  - 节点包含：供应商、Key、上游实际模型 ID。
  - 节点可新增、编辑、删除、探测，按序号故障切换。
  - 顺序用**手动输入序号**调整，不做拖拽。

两个页签顶部都显示当前生效的分流策略与一句话解释，策略本身在系统设置中修改。

### 2.4 系统设置

**回答的问题**：运行模式、分流策略、超时、冷却、中枢与运维参数怎么配？

- 双列紧凑排版，按设置组分区。
- 表单项使用统一的 `SettingRow`，说明文字紧贴字段。
- “保存修改”只保存当前草稿；“放弃修改”回到上次保存值；“恢复默认”回到推荐值。
- 网关卡片、运行模式徽章、导出配置只读取**已保存设置**。

## 3. 信息架构与数据流

### 3.1 唯一数据源

| 数据 | 唯一来源 | 说明 |
| --- | --- | --- |
| 供应商 / Agent 模型 / 知识库节点 / 设置 | `src/hooks/useConsole.ts` | 页面不各自持有业务数据 |
| 语义文案与颜色 | `src/components/common/semantics.ts` | 协议、来源、健康状态、分类、路由策略 |
| 通用组件 | `src/components/ui/` | 按钮、徽章、卡片、输入、弹窗、Toast |
| 版本号 / 网关地址 / 适配版本默认值 | `src/lib/constants.ts` | 不在组件里写死 |
| 中枢可拉取的供应商与 Key | `src/data/mock.ts` 的 `vaultProviderCatalog` / `vaultKeyCandidates` | 演示按需拉取，不重复维护 |
| 网关可用模型 | Agent 模式读 `models`；KB 模式读固定四类 + `kbCandidates` | 不维护静态模型名数组 |
| 网关客户端 Key | `savedSettings.proxy_api_key` | 不在网关对象里重复保存 |
| 当前运行模式 | `savedSettings.run_mode`，并受宿主能力约束 | 徽章与设置保存值保持一致 |
| 部署形态能力 | `src/lib/host.ts` 的 `HOST_CAPABILITIES` | 页面按能力显隐，不在各处散落 `vm/edgeone` 判断 |

### 3.2 草稿与已保存

- 设置页编辑的是 `settingValues`（草稿）。
- `savedSettings` 是最近一次保存后真正生效的设置。
- 网关卡片、运行模式徽章、导出配置、底层 JSON 使用 `savedSettings`。
- 设置页保存时同时更新两者；放弃修改只回滚草稿。

### 3.3 本地存储

- 键名：`ocrproxy.console.v1`。
- 快照包含 `version / providers / models / kbCandidates / settings`。
- 读取旧快照时补齐 `provider.adapterVersion`，默认 `V.20260801`，避免旧数据在界面上出现空版本。
- 旧快照没有 `kbCandidates` 时，从旧的 `models` 中按非 chat 分类拆出候选节点，避免知识库配置丢失。
- 快照版本不匹配或结构损坏时回退到种子数据，不抛错。

### 3.4 只读与可写

- VM 端从中枢同步的供应商与 Key 只读：显示锁，不可编辑，但仍可删除本地副本。
- 本地 Key 可添加、编辑、删除；改名时同步更新 Agent 绑定与知识库节点引用。
- EdgeOne 的客户端 Key 由环境变量注入，页面内只读。
- 删除供应商、删除 Key、重启服务等不可逆动作必须二次确认。

### 3.5 部署形态与能力差异

两个版本共用同一套页面与组件；差异只通过 `HOST_CAPABILITIES` 控制，不复制页面。

| 能力 | VM 自托管 | EdgeOne 边缘版 |
| --- | --- | --- |
| 运行模式 | Agent / 知识库 | 固定 Agent |
| 知识库页签与入库总览 | 显示 | 隐藏 |
| 错误日志 | 显示 | 隐藏 |
| 中枢客户端（拉取供应商 / Key） | 可用 | 不可用 |
| 客户端 Key | 可编辑 | 只读（环境变量注入） |
| 系统运维（更新 / 重启 / 解除冷却） | 显示 | 隐藏 |
| Agent 总览数据 | 今日累计 | 当前快照 |
| 供应商默认来源 | 本地配置 | 中枢统一 |

规则：显隐统一查能力矩阵；只有形态固有文案与新建供应商的默认来源可以直接判断宿主类型。

### 3.6 防止重复的做法

新增功能前先检查：

- 这个文案/颜色/状态是否已经在 `semantics.ts` 有定义？
- 这个选项数组是否在别的弹窗里出现过？出现两次就上移到 `semantics.ts`。
- 这个数据是否能从现有状态派生？能派生就不要新增静态副本。
- 这个字段是否真的会展示或导出？不展示也不导出的字段不要加。

## 4. 视觉系统

### 4.1 颜色

颜色只出现在小面积标签、图标和状态点上，不铺大面积背景，不抢主操作。

| 含义 | 色板 | 使用位置 |
| --- | --- | --- |
| 主操作 / Chat | `primary` 蓝 | 主按钮、Chat 协议徽章、中枢来源、选中态 |
| Messages | `violet` 紫 | Messages 协议徽章与协议选择 |
| Responses | `teal` 青 | Responses 协议徽章与协议选择 |
| 正常 | `success` 绿 | Key 正常、今日累计 |
| 未调用 | `neutral` 灰 | Key 未调用、本地来源、普通分类 |
| 限流 / 超时 | `warning` 橙 | 429、504、失败率超阈值 |
| 异常 / 欠费 | `danger` 红 | 5xx、401、Key 异常或欠费、危险操作 |
| 免 Key | `info` 天蓝 | 免 Key 来源、KB 分类 |

规则：

- **禁止**在组件里写 `bg-red-500`、`text-blue-600` 这类原始 Tailwind 色板。
- 所有颜色走 `Badge tone` 或 `semantics.ts` 的映射。
- 同一个含义在所有页面必须同色，不能这页叫“中枢”是蓝色、那页又变紫色。
- 状态点 `Dot` 只用于表格内快速扫读，不单独承担文字含义。

### 4.2 字体

| 层级 | 字号 | 字重 | 用途 |
| --- | --- | --- | --- |
| 页面标题 / 关键指标 | 24px / `text-xl` | 600 | `PageHeader` 的 h1、概览大数字 |
| 弹窗标题 | 16px / `text-base` | 600 | `Dialog` 标题 |
| 区块标题 | 14px / `text-sm` | 600 | 卡片标题、分组标题 |
| 模型标题 | 18px / `text-lg` | 600 | 模型卡主标识，等宽字体 |
| 正文 | 14px / `text-sm` | 400 | 表单、说明、表格主内容 |
| 次要正文 | 12px / `text-xs` | 400/500 | 辅助说明、表格次要列 |
| 元信息 | 11px | 400/500 | 时间、计数、提示、表头 |
| 紧凑标签 | 10px | 500/600 | 徽章、胶囊、模型卡元信息 |

规则：

- 数字使用 `.tnum`，ID、Key 别名、URL、版本号使用 `font-mono`。
- 除上述 10 / 11 / 12 / 14 / 16 / 18 / 24 七档，不再引入新的任意字号。
- 不使用 17px、19px 这类“看起来差不多”的中间值。

### 4.3 间距

- 基础栅格 4px；常用间距：4 / 8 / 12 / 16 / 20 / 24 / 32。
- 页面区块之间：16–24px。
- 卡片内边距：20px；紧凑列表行：10–16px。
- 工具栏与列表之间用 1px 分隔线，不额外加阴影。
- 同一行内元素间距 6–8px；分组之间 12px。

### 4.4 圆角与阴影

| 元素 | 圆角 |
| --- | --- |
| 页面卡片、弹窗 | 16px（`rounded-2xl`） |
| 按钮、输入框、下拉框 | 12px（`rounded-xl`） |
| 行内小标签、序号输入 | 8–12px |
| 胶囊、状态标签、Key 胶囊 | `rounded-full` |

- 阴影只用 `shadow-sm`；弹窗和移动端抽屉可用 `shadow-xl`。
- 优先用 1px 边框分隔层级，不靠重阴影。
- 子元素圆角不得大于父容器圆角。

### 4.5 图标

- 统一使用 Lucide 线性图标。
- 尺寸：行内操作 14px（`h-3.5 w-3.5`）；导航与关闭 16px（`h-4 w-4`）；空状态 20px（`h-5 w-5`）。
- 同一动作全站复用同一图标：编辑 `Pencil`、删除 `Trash2`、复制 `Copy`、添加 `Plus`、探测 Key `Zap`、探测上游模型 `Radar`、从中央拉取 `CloudDownload`、切换 `ArrowLeftRight`、锁定 `Lock`。
- 纯图标按钮必须同时有 `title` 与 `aria-label`。
- 图标不单独承担语义，旁边要有文字或 `aria-label`。

### 4.6 动效

- 只做颜色、透明度、阴影、位移的轻量过渡，150–200ms。
- 不使用弹跳、旋转等分散注意力的动画。
- 加载态用旋转指示器；不要用骨架屏掩盖真实空状态。

## 5. 组件规范

### 5.1 页面骨架

```tsx
<PageHeader
  title="页面标题"
  description="一句话说明这个页面能做什么"
  actions={<Button variant="primary">主操作</Button>}
/>
<SectionCard title="区块标题" description="可选说明">
  ...
</SectionCard>
```

- 一个页面只有一个 `PageHeader`。
- 主操作放在页头右侧；每屏最多一个 `primary` 按钮。
- 区块用 `SectionCard`；列表型区块 `contentClassName="p-0"`。

### 5.2 按钮

| 场景 | 用法 |
| --- | --- |
| 页面主操作、保存 | `variant="primary"` |
| 次要操作、工具栏、取消 | `variant="secondary"`（默认） |
| 行内纯图标、弹窗关闭 | `variant="ghost"` |
| 删除、重启等破坏性操作 | `variant="danger"` |

- 默认按钮就是 `secondary`，不要再写透明无边框按钮充当次要操作。
- 白色/透明按钮必须有可见边框或底色；用户不应该靠猜知道哪里能点。
- 尺寸：`sm` 用于表格/工具栏，`md` 用于页头/弹窗，`icon-sm` 用于纯图标。
- 异步按钮使用 `loading`，加载时自动禁用。
- 按钮默认 `type="button"`，避免误触发表单提交。
- 纯图标按钮必须有 `title` 与 `aria-label`。

### 5.3 徽章与胶囊

- `Badge` 只用于短状态、协议、来源、分类；不塞长句。
- Key 胶囊结构固定：`别名 · 来源 · 锁/删除`。
- 状态徽章文案固定：正常 / 未调用 / 429 限流 / 异常 / 欠费。
- 分类徽章用中性色；只有协议、来源、健康状态使用语义色。
- 不使用彩色头像、首字母圆形标识；名称本身已经足够识别。

### 5.4 列表与表格

**供应商列表**：单列行式布局，适合“名称 + 元信息 + Key 胶囊”的纵向阅读。

**Agent 绑定表 / 知识库节点表 / 错误日志表**：表格用于多列对比；必须支持横向滚动，最小宽度按列数设置。

知识库每个虚拟模型一张卡，卡片头固定“分类名 + model=\”类型\” + 节点数”，紧跟节点表；空模型就地在卡片内给出“挂载第一个节点”。

通用规则：

- 表头 11px、中性色，不再加粗成视觉噪音。
- 行高 40–48px；行间用 1px 分隔线。
- 主标识最多两行，重复信息删除。
- 空列表用 `EmptyState`，搜索无结果用轻量文字 + “清除搜索”，不要用整块空状态。

### 5.5 表单

- 使用 `Field` 包裹标签、控件、说明。
- 标签 12px；说明 11px；错误提示 10–11px 且用 `danger`。
- 输入框统一 36px 高；紧凑工具栏可用 32px。
- 下拉框统一使用 `Select`，箭头由 `.select-chevron` 提供。
- 密码/密钥输入使用 `font-mono`；支持显示/隐藏。
- 必填项实时校验，不满足时禁用保存按钮。

### 5.6 弹窗

- 新增/编辑用 `Dialog`，破坏性确认用 `ConfirmDialog`。
- 弹窗结构：图标 + 标题 + 说明 + 内容 + 底部操作。
- 底部操作右对齐：取消（secondary）在左，确认（primary/danger）在右。
- 点击遮罩和 Esc 关闭；关闭后重置表单草稿。
- 弹窗宽度只用 `md` / `lg`，不新增无用的尺寸档。

### 5.7 Toast

- 成功操作：默认样式，标题说结果。
- 信息性操作：`variant: 'info'`。
- 失败/冲突：`variant: 'error'`。
- 文案格式：标题是结果，描述是影响；例如“Key 已删除 / 关联绑定已清理”。

### 5.8 空状态

- 使用 `EmptyState`，图标 20px。
- 标题说明“没有什么”，描述说明“下一步做什么”，可带一个主操作。
- 搜索无结果、筛选无结果、真正无数据要区分文案。

## 6. 交互规范

### 6.1 搜索

- 供应商搜索只匹配**名称与 ID**，不匹配 Key 别名。
- 排序优先级：完全匹配 → 前缀匹配 → 包含匹配。
- 例如输入 `b`，`B.AI` 必须排第一，而不是因为某个 Key 叫 `backup` 被提前。
- 搜索框放在列表顶部工具栏，不放在侧边。
- 新增供应商后清空搜索词，确保新行和“添加 Key”表单可见。

### 6.2 排序

- 默认“名称 A–Z”。
- 可选“名称 Z–A”“Key 数量多到少”。
- 排序控件与搜索同处顶部工具栏，右侧显示匹配数量。
- 排序不改变底层数据顺序，只影响当前视图。

### 6.3 手动排序

- Key / 知识库节点顺序用输入框，范围 `1..N`，只接受整数。
- 回车或失焦提交；非法值变红并恢复原序号。
- 只有 1 个节点时输入框禁用。
- 不实现拖拽排序。
- 顺序只影响当前模型或当前分类，不改变其他模型的节点顺序。

### 6.4 切换、探测、删除

- 当前主力 Key 显示“使用中”徽章，不再显示“切换”按钮。
- 非主力 Key 提供“切换”；切换后该行高亮。
- 探测中按钮进入 loading；成功后更新健康状态与延迟。
- 知识库节点探测与 Agent Key 探测使用同一套状态色和加载反馈。
- 移除绑定、删除 Key、删除供应商都要二次确认；删除知识库节点属于可撤销配置，用 Toast 反馈即可。
- VM 端中枢 Key 不显示编辑按钮，只显示锁与说明；删除仍可用，删除只影响本地副本。

### 6.5 版本与来源

- 适配版本固定展示在供应商名称后，默认 `V.20260801`。
- 旧数据没有版本时用默认值补齐，不显示空白。
- 中枢来源用蓝色 + 锁；本地来源用灰色。
- 协议徽章紧跟在名称/模型名后，不能拆到另一行成为孤立信息。

### 6.6 响应式

- 桌面优先，侧边栏 240px；小于 `lg` 时收起为抽屉。
- 表格允许横向滚动，不把列硬压成两行。
- 工具栏在窄屏纵向排列，搜索框占满宽度。
- 弹窗在手机端从底部出现，最大高度 92vh。

### 6.7 无障碍

- 所有交互元素可键盘聚焦，焦点样式统一 `shadow-focus`。
- 纯图标按钮必须有 `aria-label`。
- 表单控件必须有 label 或 `aria-label`。
- 状态不能只用颜色表达，必须有文字。
- 点击区域不小于 28×28px。

## 7. 新增页面清单

新增页面前逐项确认：

1. **功能真实**：后端或现有数据能支撑吗？没有就暂时不做。
2. **页面语义**：用一句话说清“这个页面以什么为单位、用户来做什么”。
3. **路由**：在 `PageId` 与 `NAV_ITEMS` 增加一项；页面标题从导航自动派生，不再手写第二份。
4. **页头**：一个 `PageHeader`，标题、描述、最多一个主操作。
5. **状态**：业务数据放 `useConsole`，页面只接收 props 与 actions。
6. **部署形态**：先确认 VM / EdgeOne 能力矩阵；差异走 `HOST_CAPABILITIES`，不复制页面。
7. **语义**：新增状态/分类先补 `semantics.ts`，再写组件。
8. **组件**：优先复用 `Button / Badge / Card / SectionCard / Input / Select / Field / Dialog / EmptyState / OrderInput`；不复制一套相似组件。
9. **选项**：协议、分类、来源、路由策略等选项从 `semantics.ts` 或种子数据读取，不在页面里再写数组。
10. **数据派生**：能从现有状态算出来的，不新增静态副本。
11. **完整性**：空状态、搜索无结果、加载态、错误提示、危险确认都补齐。
12. **响应式**：窄屏下工具栏、表格、弹窗都可用。
13. **验证**：`npx tsc -b`、`npx eslint src`、`npm run build`、`curl -sf http://127.0.0.1:8000/` 全部通过。

## 8. 代码约定

### 8.1 目录

```
src/
  components/
    common/      # 语义、徽章、复制按钮
    dashboard/   # 概览
    layout/      # 外壳与导航
    models/      # 模型及路由
    providers/   # 供应商
    settings/    # 系统设置
    ui/          # 通用组件
  data/          # 种子数据与设置定义
  hooks/         # 业务状态
  lib/           # 常量、宿主能力与工具
  types.ts
```

- `lib/host.ts` 只描述部署形态能力，不承载页面状态。
- 预览环境允许在顶栏切换 VM / EdgeOne 核对差异；正式部署由宿主注入 `__HOST_KIND__` 自动识别。

- 页面私有组件放在对应页面目录；跨页面复用的才上移到 `common/` 或 `ui/`。
- 语义映射只放在 `common/semantics.ts`；组件文件只导出组件，避免热更新规则报错。

### 8.2 命名

- 组件 PascalCase；函数与变量 camelCase；常量 UPPER_SNAKE_CASE。
- 事件回调以 `on` 开头；布尔值以 `is / has / can / show` 开头。
- 颜色、状态、协议等联合类型使用单数名词。

### 8.3 样式

- 只用设计 token 与约定字号；不新增原始色板。
- 条件 class 用 `cn()`，不要手拼字符串。
- 重复三次以上的样式组合，抽成组件或常量。
- 不写内联 `style`，除非是动态数值且无法用 class 表达。

### 8.4 外部数据

- 隔离预览中禁止直连第三方 `http(s)://`。
- 需要外部 JSON 时使用 `@/lib/ext` 的 `previewFetch`；需要外部脚本时使用 `loadExtScript`。
- 不手写 `/content/__ext/...`，不改每个项目的 Vite `server.proxy`。

### 8.5 版本与常量

- 应用版本、网关地址、适配版本默认值统一放 `src/lib/constants.ts`。
- 组件里不写 `v2026.10.26`、`V.20260801` 这类字面量。
- 设置默认值从 `settingGroups` 派生，只有额外字段才在 `defaultSettings` 补。

## 10. 快速对照

**应该做**

- 先问“这个页面以什么为单位、用户来做什么”。
- 名称在前，元信息在后，操作在右。
- 一个含义一种颜色；一个动作一个图标。
- 能派生就不复制；能复用就不新写。
- 危险操作有确认，空状态有下一步。
- 按钮看得见、点得到、有说明。

**不要做**

- 没有功能支撑的搜索、趋势、用户、权限页面。
- 同一份数据在多个文件里各存一份。
- 一个页面出现两套按钮、两套圆角、两套状态色。
- 拖拽排序、隐藏操作、白底白字。
- 在供应商列表展示 Base URL 等配置细节。
- 在模型与 Key 列表之间塞统计块打断阅读。
- 为了“看起来丰富”而展示没有实际用途的字段。
