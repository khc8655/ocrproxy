# OCRProxy 控制台 · UI 重设计

对 [OCRProxy](https://github.com/khc8655/ocrproxy) 管理后台的界面重构版本。原项目把页面结构、样式与交互分散在多个脚本里，卡片、按钮、表格、弹窗各用一套尺寸与颜色，信息层级重叠。这次重做把视觉与交互统一到一套组件与 token 上，只保留原控制台已有的功能，不引入搜索、用户中心、请求趋势等没有实际接口的界面。

新增页面前请先阅读 [设计规范](./DESIGN-SPEC.md)。规范覆盖页面语义、颜色与字号、组件用法、交互规则、数据来源和新增页面清单。

## 设计原则

- **一套组件**：按钮、徽章、卡片、输入框、表格、弹窗、Toast 全部共用 `src/components/ui`，不再出现同一层级三四种规格。
- **一套尺度**：圆角、间距、字号、阴影都来自设计 token；页面间距按 4px 栅格递增。
- **信息分层**：页头（标题 + 主操作）→ 内容卡片 → 辅助说明，危险操作单独归类。
- **状态一致**：正常、限流、异常、欠费、未调用使用同一套状态标记；本地 / 中枢 Key 使用同一套来源标记。
- **图标一致**：统一使用 Lucide 线性图标；行内操作 14px、导航与关闭 16px、空状态 20px。纯图标按钮必须带 `title` 与 `aria-label`，同一动作始终复用同一图标。
- **按钮可辨**：文字按钮使用可见底色或描边；透明按钮只用于行内、图标型操作，避免白底白字看不出来。
- **只呈现真实功能**：概览只展示网关、Agent / 知识库统计与错误日志；不虚构流量图、搜索、用户与权限界面。
- **双形态共用**：VM 自托管与 EdgeOne 边缘版共用同一套页面；知识库、错误日志、系统运维、中枢客户端等差异由宿主能力矩阵控制，不复制页面。

## 配色约定

同一含义在所有页面使用同一种颜色，颜色只出现在小面积标签上，不抢主操作。

| 含义 | 颜色 | 覆盖范围 |
| --- | --- | --- |
| Chat 协议 | 蓝 | 协议徽章、新增 / 编辑供应商与模型时的协议选择 |
| Messages 协议 | 紫 | 同上 |
| Responses 协议 | 青 | 同上 |
| 中枢来源 | 蓝 | 供应商来源、Key 胶囊、绑定列表 |
| 本地来源 | 灰 | 同上 |
| 免 Key | 天蓝 | 同上 |
| Key 正常 | 绿 | 模型绑定列表、编辑模型弹窗 |
| Key 未调用 | 灰 | 同上 |
| Key 限流 | 橙 | 同上，与概览中的 429 / 超时一致 |
| Key 异常 / 欠费 | 红 | 同上，与概览中的鉴权失败 / 5xx 一致 |

## 页面

| 页面 | 内容 |
| --- | --- |
| 概览 | 接入网关与当前模式可用模型（Agent 模型或知识库四类虚拟模型，协议实时取自状态）；Agent 总览（VM 今日累计、EdgeOne 当前快照）；知识库入库总览与错误日志（仅 VM） |
| 供应商 | 顶部名称搜索与排序；名称后集中展示来源 / Key 数量 / 适配版本 / 协议 / RPM；Key 胶囊支持编辑与删除，VM 端中枢 Key 带锁只读；支持从中枢按需拉取供应商、单条或批量升级适配规则 |
| 模型及路由 | Agent 与知识库两个页签：Agent 以模型为单位切换 Key、输入序号排序、探测上游模型；知识库按 4 个虚拟模型管理候选节点，支持挂载、编辑、删除、探测与排序 |
| 系统设置 | 按宿主与运行模式过滤字段：运行模式、分流策略、超时并发、冷却避让、凭据中枢、系统运维与配置数据；导出与底层 JSON 只读取已保存设置 |

## 本地运行

```bash
pnpm install
pnpm dev        # http://localhost:8000
pnpm build      # 生产构建
```

## 数据说明

当前版本是前端原型：供应商、模型、知识库节点、统计与日志来自 `src/data/mock.ts`，操作结果保存在浏览器 `localStorage`，不会请求真实上游。接入后端时替换 `src/hooks/useConsole.ts` 中的数据操作即可，页面组件无需改动。种子数据、中枢可拉取清单、网关可用模型与客户端 Key 均从单一来源派生，不在页面里维护静态副本。

顶栏的 VM / EdgeOne 切换只用于预览两种部署形态的差异；正式环境由宿主注入 `__HOST_KIND__` 自动识别。
