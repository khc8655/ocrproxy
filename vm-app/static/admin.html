              1. 运行模式与客户端鉴权 (Run Mode & Client Auth)
            

            全局通用

              2. 核心分流调度策略 (Key Routing Strategy)
            

            分流调度
          

          

            

              
              
              

                🔒 纯手动直通模式已生效：系统将直接使用各 Agent 模型指定的当前激活 Key，绝不进行自动切换；所有自动重试、熔断与冷却避让已自动停用，上游响应（含 200/429/500）完全 100% 原始透传。
              

              智能体编程场景（Cursor / Cline）推荐「粘性故障转移」，可保持会话连接与 KV Cache 稳定性，避免频繁切回限流 Key。
            

            

              
              
              知识库无状态批量入库（Embedding / OCR / Rerank）推荐「轮询负载均衡」，可均匀打散流量并大幅提升入库吞吐量。
            

          

        


        
        

          

            

              3. 超时时钟与重试预算 (Timeouts & Retry Budget)
            

            超时控制
          

          

            

              
              
              向上游单一 Key 发起请求的等待上限（秒），超时后立即切换下一候选 Key（默认 15s）
            

            

              
              
              单次客户端请求在多候选 Key 之间轮换尝试的最长总时钟（秒，默认 45s）
            

            

              
              
              单次请求最多允许尝试的候选 Key 数量上限（默认 3 次，避免无限死等）
            

            

              
              
              单厂商多个 Key 故障时最多尝试次数（默认 2 次），防止单个厂商死等超时
            

            

              
              
              Embedding / OCR / Reranker 等大文档批处理耗时计算超时（默认 60s）
            

            

              
              
              每个 API Key 在途最大并发保护，防止瞬间突发打崩配额
            

            

              

                
                
              

              遇到上游 502/504/连接超时且存在其他备用厂商时，直接跳过当前厂商所有剩余 Key 秒级切走，极大提升可用率。
            

          

        


        
        

          

            

              4. 故障避让与系统运维 (Fault Tolerance & Maintenance)
            

            容灾运维
          

          

            

              
              
              命中 RPM / TPM 速率限制时的临时避让时长（秒，默认 60s）
            

            

              
              
              上游 500/502/503/504 服务异常时的避让冷却时长（秒，默认 30s）
            

            

              
              
              连续 5xx / 宕机达到该次数时触发断路器熔断（默认 3 次）
            

            

              
              
              Key 无效或额度用尽时的主动隔离时长（秒，默认 600s / 10分钟）
            

          


          

            

              

                
每日定时平滑重启 (Daily Auto-Restart)

                
每日凌晨 04:00 自动重启服务释放内存堆（Agent 模式推荐关闭以保持会话连续；KB 模式建议开启）

              

              
            

            

              日志空间保护机制：系统底层配置了 journald 50MB 磁盘配额自动轮转（SystemMaxUse=50M, 7天保留），内存错误日志严格限定在 100 条以内，无需重启即可确保长期运行磁盘与内存零积压。
            

          


          

            

              
即时平滑重启服务 / 重载熔断状态

              
向后台发送平滑重启信号（约 2-3 秒完成），或一键清空所有 Key 的 429 冷却与熔断计数
